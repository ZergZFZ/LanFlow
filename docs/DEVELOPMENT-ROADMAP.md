# LanFlow 后续开发路线图

- 基线版本：v1.3.7
- 原则：先保护用户数据和已有桌面流程，再扩大功能范围
- 更新日期：2026-07-29

## 1. 排期原则

LanFlow 不以“复刻竞品功能数量”为目标。每个阶段只解决一类明确用户问题，并在进入下一阶段前满足可验证的完成条件。

| 原则 | 含义 |
|---|---|
| 数据优先 | 任何批量操作、迁移或自动化都必须可预览、可取消、可回归 |
| 增量演进 | 复用 WPF 客户端和已有配置，不做无业务价值的技术栈重写 |
| 本地优先 | 不把云端账户、模型服务或插件市场作为基础功能前提 |
| 可降级 | 搜索源、更新网络或外部文件不可用时，主启动器仍可正常工作 |
| 双通道发布 | 每项发布改动均要考虑 full 与 lite 的构建、安装和应用内更新 |

## 2. R1：质量基线与安全批量导入

### 用户问题

用户已整理的软件较多，手工逐项添加耗时；但让 AI 或外部工具直接写内部配置又不可控。

### 范围

- 将 `docs/import-manifest.schema.json` 作为唯一机器可读的导入契约；
- 提供最小示例和格式校验；
- 在 Core 实现读取、文本/路径规范化、存在性检查、去重和预览；
- 在 WPF 提供文件选择、预览、逐项勾选、确认和结果反馈；
- 将选中的项目一次性合并并原子保存；
- 建立 `LanFlow.Core.Tests`，覆盖规则和失败场景。

### 不包含

- LanFlow 内置 LLM；
- 自动扫描和自动分类全电脑软件；
- 静默导入；
- 直接导入、覆盖或生成内部 `config.json`；
- 命令参数、工作目录、环境变量、图标定义等复杂导入字段。

### 完成条件

1. 预览、取消和校验失败时配置不变；
2. 用户可看到新建、合并、重复和无效项；
3. 一次确认只产生一次配置写入；
4. 失败不产生部分导入；
5. 导入后项目可显示图标、启动并在重启后保留；
6. Core 测试和已有手工启动器回归全部通过。

## 3. R2：工作区快速定位

### 用户问题

用户已经把常用目标整理进 LanFlow，但项目和分组增多后，需要在不切换分组、不离开主面板的情况下通过键盘快速定位并启动已管理项目。

### 产品决策

- 继续使用现有完整主面板，不新增独立半透明悬浮搜索窗口；
- 搜索是工作区的辅助能力，不是面向整台电脑的第二套产品入口；
- Everything、资源管理器和开始菜单继续作为外部查找来源，用户找到目标后通过拖放或导入将其收纳到 LanFlow；
- LanFlow 不感知 Everything 是否安装，也不维护开始菜单、用户目录或全盘文件索引。

### 范围

- 主面板激活后支持直接输入进入搜索，无需先点击搜索框；
- 搜索所有分组中的已管理项目，并显示匹配项目所属分组；
- 支持名称、路径、命令和可选别名的模糊匹配；
- 支持上下键选择、Enter 启动、Escape 清空、使用频次排序和明确的无结果状态；
- 清空查询后恢复进入搜索前的分组、卡片布局和焦点语义；
- 将匹配、排序和选择规则放入 Core，WPF 只负责输入、展示和动作转发；
- 将现有“搜索全部软件”文案改为准确表达已管理项目范围的文案。

### 不包含

- 独立悬浮搜索窗口或第二套全局热键入口；
- 开始菜单、用户授权目录或已安装应用索引；
- Everything SDK、IPC、命令行适配器或 `IFileSearchProvider`；
- 全盘文件搜索、浏览器书签、剪贴板历史、网页命令和通用命令面板；
- Flow Launcher 插件协议兼容。

### 完成条件

1. 不依赖外部索引、搜索服务或系统应用扫描，仍可搜索并启动全部已管理项目；
2. 用户呼出主面板后可直接输入，使用上下键和 Enter 完成启动，并用 Escape 返回原工作区；
3. 搜索结果清楚显示所属分组，无结果状态不会暗示 LanFlow 已搜索整台电脑；
4. 搜索不会修改分组、项目顺序、使用次数之外的配置或进入搜索前的工作区状态；
5. 匹配和排序规则不依赖 WPF 控件，并具有自动化测试；
6. 性能目标以目标机器基准测试记录为准，而不是未经测量的承诺。

## 4. R3 / P2：工作区体验与配置演进

详细实施方案见 `docs/P2-Workspace-Experience-Development-Plan.md`。

### 用户问题

随着项目数量增多，用户需要可达、可预测的布局管理，以及在设置、启动和配置异常时不会丢失已有工作区的明确反馈。

### 范围

- 实现分组拖拽排序、导航收起和导航 / 项目区溢出的滚动可达性；
- 建立网格 / 卡片在编辑、搜索、删除、拖放和设置预览下的一致性合同；
- 统一启动失败、热键冲突、不可访问路径、保存失败等用户反馈；
- 引入配置版本、受控迁移、读取失败保护和真实配置样本回归；
- 在设置中显示配置位置，并提供不修改当前配置的显式完整备份；
- 扩充 Desktop 回归和 full/lite 发布检查。

### 不包含

- 单个分组内容折叠：当前单选分组界面下没有清晰价值；本期只实现导航收起，`Group.Collapsed` 保持兼容但不激活；
- 一键恢复备份、分组导入 / 导出或静默覆盖配置；
- 新搜索源、插件、命令执行或云端同步。

### 完成条件

1. 左侧与顶部布局均可排序，分组和项目溢出后均可访问，重启后状态保持；
2. 旧配置升级后保留分组、项目、主题、布局和热键；损坏或未来版本配置不会被空配置静默覆盖；
3. 新增设置有默认值、保存逻辑、取消回滚和重启回归；
4. 现有拖放、编辑、启动、托盘、导入和更新行为不回退；
5. 用户可打开配置目录并创建不修改当前工作区的完整备份；
6. full/lite 均可完成升级验证。

## 5. R4：轻量性与启动性能

### 用户问题

LanFlow 作为常驻托盘的轻量启动器，必须在项目数量增长、图标加载和长期运行时保持快速呼出、低干扰和可预测的资源占用。

### 范围

- 建立冷启动、静默驻留、热键呼出、首批图标显示和大工作区交互的可重复基准；
- 优化图标延迟加载、缓存、失效和失败降级；
- 检查启动路径和后台任务，避免在用户未使用相关功能时进行目录扫描或额外索引；
- 验证 full/lite 两条通道的体积、依赖、启动和更新成本；
- 记录目标机器、配置样本和测量方法，不以主观感受替代性能证据。

### 不包含

- 内置文件索引器、开始菜单索引器或 Everything 集成；
- 网页搜索、计算器、系统命令或通用命令面板；
- Flow Launcher 插件兼容、插件商店或开放网络 API；
- 为追求体积而破坏 WPF 功能、配置兼容或 full/lite 更新规则。

### 完成条件

1. 冷启动、热键呼出和首批可用时间均有基准记录及回归阈值；
2. 未使用导入等功能时不启动额外扫描或索引任务；
3. 图标或外部目标解析失败不会阻塞主面板；
4. full/lite 均通过启动、驻留、更新和真实配置回归。

## 6. 发布闸门

每个可发布版本必须同时满足：

- 产品基线、架构文档和变更日志与代码一致；
- Release 构建、Core 测试和关键手工回归通过；
- `LanFlow-{version}-full.zip` 与 `LanFlow-{version}-lite.exe` 均已生成并验证；
- 应用内更新可为对应通道匹配正确资产；
- 不存在未经说明的配置格式变化、未跟踪的破坏性行为或需要用户猜测的升级步骤。
