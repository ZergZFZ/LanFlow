# LanFlow Windows 性能与 UI 分阶段原地重构设计

- 日期：2026-07-30
- 状态：已完成讨论，待书面规格复核
- 目标分支：`windows`（上游 `dev/windows`）
- 技术路线：路线 2——基于现有 WPF 项目的分阶段原地重构

## 1. 背景

LanFlow Windows 版当前功能已基本齐备，但在 Windows 11 性能模式下使用网格视图切换分组时，存在以下明显问题：

- 新分组内容首次呈现时，大图标可能以错误尺寸短暂闪现，随后才收缩到设置尺寸。
- 分组切换会重新生成较多视觉元素，造成画面跳动和卡顿感。
- 网格布局未虚拟化，数据量增加后，布局、容器创建和图标加载成本随项目总量上升。
- 分组按钮在刷新时整体清空并重建，增加不必要的 UI 工作。
- 图标加载以同步和全局处理为主，缺少面向当前视口的优先级、缓存及过期请求取消机制。
- 主窗口和设置页存在较多内联样式、硬编码颜色与分散的视觉参数，整体观感偏粗糙。
- 设置页信息架构较弱，全部设置集中展示，预览、应用与取消的状态边界不够清晰。

本设计在不更换 WPF 技术栈、不破坏现有功能和用户习惯的前提下，优先解决首帧错误、切换卡顿和大数据量渲染问题，再逐步统一视觉系统并重构设置页。

## 2. 已确认的产品方向

### 2.1 规模目标

本次设计按以下数据规模优化：

- 单个分组约 30–100 个项目。
- 全部项目约 100–500 个。

当前数据量即使低于该范围，也采用能覆盖上述规模的架构，避免短期修补后再次重构。

### 2.2 技术路线

采用“分阶段原地重构”：

- 保留 WPF 和现有应用模型。
- 保留现有主要工作流和功能入口。
- 不迁移到 WinUI、Avalonia 或其他 UI 框架。
- 不进行与本目标无关的完整 MVVM 重写。
- 允许针对性能关键路径拆分职责、替换布局面板、调整集合更新方式和重构设置页面结构。

### 2.3 视觉方向

采用紧凑、专业、高信息密度、低装饰的桌面工具风格：

- 圆角、阴影和动效保持克制。
- 选中、悬停、键盘焦点和拖拽状态清楚但不过度强调。
- 视觉方案应适合软件长期以约 85% 透明度运行。
- 已展示的概念模板只作为视觉风格与信息层级参考，不是最终界面布局，不要求逐像素照搬。
- 主窗口以原有结构为基础做性能和视觉精修；设置页可在功能完整保留的前提下做结构性重排。

## 3. 范围与非目标

### 3.1 本次范围

- 网格、卡片及列表模式的首帧尺寸稳定性。
- 分组切换、集合更新和分组导航刷新性能。
- 图标异步加载、缓存、优先级和取消机制。
- 网格与卡片模式虚拟化。
- 点击与悬停切换分组的可配置交互。
- 顶部/左侧分组导航及标签尺寸相关设置。
- 主界面设计令牌与公共样式体系。
- 双透明度模式及可调透明度。
- 设置页信息架构、预览、应用和取消机制。
- 对性能关键职责进行有边界的代码拆分。
- 回归测试、性能测量及发布前验证。

### 3.2 非目标

- 不复制概念模板的完整布局。
- 不同时显示顶部和侧边两套分组导航。
- 不新增右侧分组栏；概念模板中出现的右侧分组栏已明确排除。
- 不移除现有网格、列表或卡片显示模式。
- 不移除现有顶部/左侧分组位置选择能力。
- 不借机重写全部业务层、数据存储层或导航体系。
- 不引入大范围、持续性的模糊或高成本视觉特效。
- 不以动画掩盖性能问题。

## 4. 当前实现问题与根因

当前实现中的主要性能链路如下：

1. `SelectedGroup` 变化后，`VisibleItems` 以 `IEnumerable` 形式整体替换。
2. 列表控件重新生成项目容器。
3. `ItemContainerGenerator.StatusChanged` 在渲染优先级调度 `ApplyItemMetrics()`。
4. `ApplyItemMetrics()` 遍历容器，并递归查找 `ItemIcon` 和 `ItemName`。
5. 图标和文字尺寸在可能已经发生的首帧渲染之后才被应用。
6. 网格使用普通 `WrapPanel`，屏幕外项目仍参与容器创建和布局。
7. `RefreshGroupTabs()` 清空并重建所有分组按钮。
8. 图标加载缺少视口优先级、细粒度缓存和过期请求取消。

因此，“大图标闪现”不是单一动画问题，而是项目模板初始尺寸、容器再生成、后置视觉树修改和同步图标处理共同导致的首帧不稳定。

## 5. 目标架构

### 5.1 渲染原则

- 所有影响布局的项目尺寸在首帧渲染前通过绑定或样式确定。
- 图标未就绪时使用固定尺寸占位区域，异步结果只替换内容，不改变布局。
- 禁止在分组切换路径上调用同步 `UpdateLayout()`。
- 禁止在每次分组切换时对所有项目执行递归视觉树查找。
- 不通过缩放动画制造“从大到小”的图标变化。
- UI 线程只负责提交当前可见状态，不负责批量解码或处理全部分组图标。

### 5.2 稳定集合与差量更新

`VisibleItems` 改为稳定的可观察集合或稳定的集合视图：

- 分组切换时不替换整个 `IEnumerable` 引用。
- 根据目标分组计算差量或批次更新。
- 对大量变化采用合并通知或受控刷新，避免逐项触发昂贵布局。
- 选中项、焦点项和滚动位置的保留策略由显示模式决定，并在同分组刷新时尽量维持。
- 快速连续切换只提交最新有效请求，过期切换不得覆盖当前状态。

### 5.3 虚拟化布局

网格和卡片模式使用支持项目容器回收的虚拟化网格/换行布局；列表模式继续使用并验证现有虚拟化能力。

虚拟化方案必须同时支持：

- 容器回收。
- 当前视口及合理缓冲区的项目生成。
- 键盘方向导航。
- 单击选择和双击启动。
- 项目拖拽、排序和跨分组拖放。
- 拖拽靠近边缘时自动滚动。
- 搜索过滤后的正确布局和索引映射。
- 网格、卡片和列表模式之间切换。

若现成面板无法完整满足拖放和键盘导航要求，应实现边界清晰的自定义虚拟化面板或在成熟开源实现基础上做适配；不得退回到“全部生成，仅优化图标”的方案。

### 5.4 图标加载管线

图标服务改为分层异步管线：

1. 模板先显示固定大小占位区域。
2. 当前视口图标进入最高优先级队列。
3. 视口附近缓冲区进入次高优先级。
4. 当前分组其余项目在空闲时加载。
5. 最近访问或相邻分组仅在 UI 空闲且无高优先级任务时预热。
6. 分组、搜索结果或视口变化后，取消不再需要的低优先级请求。
7. 解码与文件读取在后台完成，UI 线程只提交仍然有效的结果。

内存缓存键至少包含：

- 文件路径或稳定资源标识。
- 请求显示尺寸。
- 文件版本信息或最后修改时间。
- 会影响图标结果的主题变体（如适用）。

可复用 `ImageSource` 在跨线程使用前冻结。缓存需要容量上限和淘汰策略，避免 500 个项目、多尺寸和多主题组合长期累积。首阶段以进程内内存缓存为主，不把持久化磁盘图标缓存作为必要条件。

### 5.5 分组导航控制

- 保留“顶部”与“左侧”两种分组导航位置。
- 任一时刻只呈现一套分组导航；切换位置时复用同一数据源和选中状态。
- 升级后保留用户现有的分组位置配置。
- 分组新增、删除、重命名和排序时做差量更新，不在普通切换时清空重建全部按钮。
- 选中反馈应先于内容加载，使用户点击后立即获得确认。

新增或完善以下设置：

- 分组标签大小：统一控制标签高度和内边距，作为一个用户设置。
- 分组标签字体大小：独立控制文字字号。
- 左侧导航宽度：仅在左侧布局时显示并生效。
- 标签最大宽度或名称截断：防止长名称破坏顶部或左侧布局，完整名称通过工具提示等方式可访问。

首版设置边界采用设备无关像素（DIP）：

- 分组标签大小：28–52 DIP，默认 36 DIP；控制高度与纵向/横向内边距，不控制字体。
- 分组标签字体大小：11–18 DIP，默认 13 DIP。
- 左侧导航宽度：96–280 DIP，默认沿用当前 132 DIP。
- 顶部标签单项最大宽度：180 DIP；左侧标签可用宽度跟随导航宽度扣除内边距。

超长名称统一使用省略号，并通过工具提示和可访问名称提供完整文本。设置预览和配置读取都必须钳制到上述范围，避免旧配置或手工修改导致标签覆盖主要内容区或形成不可操作状态。

### 5.6 分组切换交互

提供两种设置：

- 点击切换：默认值。
- 悬停切换：可选。

悬停切换采用约 200 ms 意图延迟：

- 指针在延迟结束前离开时取消切换。
- 在多个标签间快速移动时合并请求，只处理最后一个仍有效的目标。
- 已选中分组不重复触发加载。
- 拖拽跨分组时可以复用悬停意图机制，但拖拽状态与普通浏览状态分开管理，避免误切换。

## 6. 动效与交互反馈

### 6.1 分组过渡

仅在内容已缓存且系统允许动画时使用轻量过渡：

- 时长 80–120 ms。
- 以透明度变化和极小位移为主。
- 不使用图标缩放、弹跳或大范围页面位移。
- 未缓存内容保持固定占位，结果到达时不改变项目几何尺寸。

### 6.2 动画偏好

设置页提供：

- 跟随系统（默认）。
- 始终开启。
- 始终关闭。

“跟随系统”遵循 Windows 减少动画或关闭动画的系统偏好。关闭动画时，状态仍需清晰切换，不依赖过渡表达选中或焦点。

### 6.3 拖拽反馈

- 拖拽预览使用独立、轻量的视觉层，不复制复杂项目模板。
- 拖拽提示、插入位置和目标分组反馈保持完全不透明且可辨识。
- 虚拟化不得破坏跨分组拖拽、自动滚动和排序结果。

## 7. 双透明度系统

### 7.1 模式

设置页提供两个互斥模式：

#### 分层透明（推荐）

- 窗口背景材质和表面使用用户选择的透明度。
- 文字、图标、焦点框、选中态、拖拽反馈和关键交互元素保持完全不透明。
- 主要用于兼顾桌面透出效果和内容可读性。

#### 整窗透明（兼容）

- 窗口及其全部内容共享同一透明度。
- 保留现有整体透明行为，供偏好原有效果的用户选择。

### 7.2 数值与状态规则

- 可调范围：40%–100%。
- 默认值：85%。
- 两种模式分别记忆各自最近使用的透明度。
- 滑块持续显示精确百分比。
- 提供“恢复 85%”操作，只修改当前模式的预览值。
- 拖动滑块时节流预览，避免每个原始指针事件都触发完整窗口重绘。
- 松开滑块或执行应用时提交设置，不在每个滑块刻度写入持久化存储。
- “应用/保存”持久化当前模式与两个模式的独立数值。
- “取消”恢复打开设置页时的模式和透明度快照。
- 模式切换时立即预览该模式上次记忆的数值，但在应用前不写入持久化配置。

### 7.3 85% 透明度下的视觉约束

- 主文字、次文字、分隔线和选中态必须在常见浅色与深色桌面背景上保持可辨识。
- 半透明表面需有适度色调或遮罩，不能只降低 Alpha 而丢失层级。
- 不使用动态全窗模糊作为可读性的唯一保障。
- 焦点、拖拽、错误与警告状态不随背景透明度减弱。

## 8. 设计系统与主界面精修

### 8.1 资源组织

建立共享资源字典，并按层次组织设计令牌：

1. 基础令牌：颜色、字号、字重、间距、圆角、阴影、图标尺寸、动画时长。
2. 语义令牌：表达用途，不绑定具体颜色。
3. 组件令牌：在分组标签、项目卡片、设置控件等组件内部使用。

核心语义资源至少包括：

- `WindowBackgroundBrush`
- `SurfaceBrush`
- `ItemHoverBrush`
- `ItemSelectedBrush`
- `PrimaryTextBrush`
- `SecondaryTextBrush`
- `FocusBorderBrush`
- `GroupTabSelectedBrush`

不得继续在新代码中散布同义的硬编码颜色、圆角和间距。迁移采用逐组件替换，不要求一次性重写所有历史样式。

### 8.2 项目模板

- 图标、文字和卡片尺寸全部在 XAML 模板首次测量前确定。
- 网格、列表和卡片模式保留各自的信息密度与操作习惯。
- 悬停效果仅改变颜色、边框或轻量阴影，不使用影响布局的缩放。
- 文字截断规则统一，完整名称可通过工具提示或可访问名称读取。
- 选中、键盘焦点和悬停是不同状态，不能只依赖同一种背景色表达。

### 8.3 主窗口布局边界

- 保留现有主窗口的主要结构、工具入口、搜索、分组位置选择和内容模式。
- 不引入概念模板中的额外右侧分组区。
- 主要内容区在顶部和左侧分组布局之间切换时，不应出现重复导航或短暂双份导航。
- 视觉精修以统一密度、对齐、颜色和状态反馈为主，不在本次重排全部业务入口。

## 9. 设置页重构

### 9.1 页面结构

设置窗口改为三段式结构：

- 左侧：固定分类导航。
- 右侧：当前分类的可滚动内容。
- 底部：固定操作区，放置应用/保存、取消等操作。

建议分类：

1. 外观与主题。
2. 布局与项目。
3. 分组标签。
4. 透明度与材质。
5. 交互与动画。
6. 启动与快捷键。
7. 性能与缓存。
8. 关于。

最终分类可根据现有设置数量小幅合并，但不得把所有设置重新堆回单一长页面。

### 9.2 信息密度

- 使用清晰的分区标题、说明文字和紧凑控件行。
- 避免“每个设置一个大卡片”的低信息密度布局。
- 相关设置放在同一分区，共享说明和状态。
- 依赖项动态显示或禁用，例如左侧导航宽度仅在分组位于左侧时出现。
- 危险或会明显改变行为的设置提供简短说明，但不使用冗长弹窗打断普通调整。

### 9.3 预览事务

打开设置窗口时建立原始配置快照和工作副本：

- 所有控件编辑工作副本。
- 支持预览的设置通过统一预览会话临时应用到主窗口。
- “应用/保存”将工作副本写入持久化配置，并更新原始快照。
- “取消”恢复原始快照及主窗口预览状态。
- 窗口关闭时如有未保存变更，提示用户保存、放弃或返回设置。
- 预览更新需合并与节流，避免字号、标签大小和透明度滑块连续变化造成重布局风暴。

该机制覆盖主题、项目尺寸、分组位置、分组标签尺寸、字体大小、透明度和动画偏好等可预览设置，避免每个控件各自实现撤销逻辑。

## 10. 代码职责拆分

针对当前较大的 `MainWindow.xaml.cs` 做与本项目直接相关的职责抽取：

- 布局与显示设置协调器：负责显示模式、项目尺寸和布局参数。
- 图标服务/管线：负责异步请求、优先级、缓存、取消和结果有效性。
- 分组导航控制器：负责顶部/左侧导航、按钮差量同步、点击/悬停意图和选中反馈。
- 拖放行为：负责拖拽预览、自动滚动、排序与跨分组投放。
- 设置预览会话：负责快照、工作副本、临时应用、提交与回滚。

拆分原则：

- 每个单元有明确输入、输出和生命周期。
- 业务模型不依赖具体视觉元素查找。
- 视觉层不直接承担文件图标解码。
- 不为追求形式完整而一次性引入全量 MVVM 重构。

## 11. 数据与设置兼容

- 现有用户分组、项目、排序、主题和快捷键数据保持兼容。
- 现有分组位置值继续映射为顶部或左侧，升级后不擅自改变。
- 现有整窗透明值迁移到“整窗透明”模式的记忆值。
- 新安装默认使用“分层透明”和 85%。
- 对已有用户，首次升级不强制切换透明模式；保持兼容行为，用户可在设置页主动选择推荐的分层透明。
- 新增设置均提供稳定默认值；读取旧配置缺少字段时不得报错。
- 配置写入继续采用现有安全写入策略，不因实时预览频繁落盘。

## 12. 分阶段实施顺序

### 阶段 1：测量与首帧修复

- 增加分组切换、容器生成、首帧稳定和图标提交的性能标记。
- 将项目尺寸前置到 XAML 绑定/样式。

## 13. 验收指标

性能测量使用 Release 构建、Windows 11、500 个总项目、当前分组 100 个项目的基准数据；同时记录硬件、分辨率、缩放比例、透明模式和冷/热缓存状态。目标如下：

- 用户选择分组后，导航选中反馈在约 50 ms 内出现；以第 95 百分位作为观察指标。
- 缓存已命中的分组在约 100 ms 内达到稳定可交互内容；以第 95 百分位作为观察指标。
- 项目首帧不存在未按设置尺寸约束的大图标。
- 普通 Windows 11 硬件上持续滚动以接近 60 FPS 为目标，不出现连续的长帧卡顿；性能报告需列出帧时间分布，而不是只给平均值。
- 分组切换过程中不执行同步的全分组图标加载。
- 分组切换过程中不执行针对全部项目的递归视觉树遍历。
- 网格和卡片模式仅生成当前视口及缓冲区需要的项目容器。
- 40%–100% 全范围透明度可用。
- 两种透明模式分别记忆数值，并能正确应用、取消和重启恢复。
- 快速点击或悬停多个分组时，最终只提交最后一个有效目标，不显示过期结果。

其中 50 ms、100 ms 和接近 60 FPS 是性能验收目标，不通过降低图像质量、取消必要反馈或破坏功能来换取。若目标硬件存在系统级限制，性能报告必须给出可复现数据和剩余瓶颈，不得以主观“感觉流畅”替代测量。

## 14. 回归测试矩阵

至少覆盖以下组合：

- 显示模式：网格、列表、卡片。
- 分组位置：顶部、左侧。
- 分组切换：点击、悬停。
- 透明模式：分层透明、整窗透明。
- 透明度边界：40%、85%、100%。
- 动画偏好：跟随系统、始终开启、始终关闭；并验证 Windows 系统动画已关闭的情况。
- 缓存状态：冷缓存、热缓存、图标文件更新后失效。
- 数据规模：小规模现有数据、单组 100 项、总计 500 项。

核心功能回归：

- 项目新增、编辑、删除和启动。
- 分组新增、重命名、删除和排序。
- 项目排序、同组拖放和跨分组拖放。
- 拖拽自动滚动和悬停切组。
- 搜索、清除搜索及搜索状态下切组。
- 键盘导航、焦点可见性和回车启动。
- 顶部/左侧切换及现有配置保留。
- 项目尺寸、标签尺寸、标签字体和左侧宽度预览。
- 主题切换。
- 设置预览、应用、取消和关闭未保存提示。
- 应用重启后的设置恢复。

## 15. 风险与控制

### 15.1 虚拟化与拖放冲突

风险：回收容器可能使拖拽索引、命中测试和自动滚动失效。

控制：虚拟化阶段同时实现逻辑索引映射和视口坐标转换，不把拖放验证推迟到最后；以跨分组拖放作为阶段 4 完成门槛。

### 15.2 异步图标结果串组

风险：旧请求晚到后覆盖当前项目或已回收容器。

控制：结果提交前校验项目稳定标识、请求版本、目标尺寸和当前绑定令牌；取消仅作为节省资源的手段，正确性不依赖取消一定成功。

### 15.3 实时预览导致重布局

风险：透明度、字号和尺寸滑块连续输入造成 UI 线程压力。

控制：预览合并、节流，布局参数只在必要边界提交；持久化仅在应用或明确提交动作发生。

### 15.4 视觉重构范围膨胀

风险：主窗口精修演变为全界面重写。

控制：概念模板只作为风格参考；阶段 5 以令牌、状态和现有组件迁移为边界，业务入口重排需另行设计批准。

### 15.5 透明度可读性

风险：40% 透明度和复杂桌面背景降低可读性。

控制：推荐分层透明；关键内容保持不透明；半透明表面保留色调遮罩；在浅色、深色和高对比背景上做视觉验证。
