# LanFlow AI 批量导入开发计划

- 状态：已实施并验证（桌面真实交互边界见第 10 节验证记录）
- 基线版本：LanFlow v1.3.7（`2097c7b`）
- 制定日期：2026-07-29
- 目标客户端：`native/LanFlow.Desktop`（WPF + .NET 8）

## 1. 目标

允许任意 AI Agent 或外部工具按照约定生成一个 `import-manifest.json`，用户在 LanFlow 中选择该文件后：

1. LanFlow 解析并校验 JSON；
2. 展示待创建分组、待导入项目、重复项和无效项；
3. 用户按分组或项目勾选；
4. 用户确认后，一次性合并到现有配置；
5. 保存成功后刷新主界面。

核心目标不是让 LanFlow 自己扫描电脑，而是建立一个稳定、可验证、可版本化的**导入契约**，把“应用发现与分类”和“LanFlow 录入”解耦。

```mermaid
flowchart LR
    A["AI Agent / 外部工具"] -->|"生成约定格式"| B["import-manifest.json"]
    B --> C["LanFlow 解析与校验"]
    C --> D["导入预览：分组、勾选、冲突提示"]
    D -->|"用户确认"| E["合并到 AppConfig"]
    E --> F["ConfigStore 原子保存"]
    F --> G["刷新主界面"]
```

## 2. 范围边界

### 2.1 本期包含

- 定义 `import-manifest` v1.0 JSON 契约；
- 提供机器可读的 JSON Schema 和可直接复制的示例；
- 从本地文件选择 `import-manifest.json`；
- JSON 解析、结构校验、字段规范化和路径检查；
- 分组与项目的预览、勾选、重复提示和合并提示；
- 用户确认后一次性写入现有 `config.json`；
- 成功、部分跳过和失败结果反馈；
- 核心解析与合并规则的自动化测试。

### 2.2 本期不包含

- 不规定 Agent 从桌面、开始菜单、注册表或其他位置扫描应用的优先级；
- 不在 LanFlow 内接入 LLM；
- 不由 LanFlow 自动调用 Agent；
- 不定义应用分类算法、提示词策略或模型选择；
- 不直接导入或覆盖完整 `config.json`；
- 不导入主题、快捷键、布局等用户设置；
- 不支持静默导入，必须经过用户预览和确认；
- v1.0 暂不扩展命令行参数、工作目录和环境变量展开。

应用数据从哪里获取、如何判断软件类别，由用户与 Agent 在生成 JSON 前自行约定。LanFlow 只负责消费符合契约的结果。

## 3. 第一性原则与关键决策

### 3.1 不直接让 Agent 修改 `config.json`

直接写现有配置看似改动最小，但风险最大：

- Agent 可能覆盖主题、热键和布局设置；
- Agent 需要理解内部 ID、默认值和兼容字段；
- 一处格式错误可能导致整个配置无法加载；
- 无法在写入前向用户展示合并结果；
- 配置结构演进会把外部 Agent 与内部实现强耦合。

因此使用独立、窄化的 `import-manifest.json`。它只描述“希望导入的分组和启动项目”，内部 ID、图标对象、使用次数和设置均由 LanFlow 负责。

### 3.2 格式不能只存在于自然语言说明中

要让不同 Agent 稳定知道输出格式，不能依赖它们猜测或记住聊天内容。格式采用三层交付：

1. `docs/import-manifest.schema.json`：唯一机器可读契约，使用 JSON Schema Draft 2020-12；
2. `docs/import-manifest.example.json`：最小可用示例；
3. 本计划中的字段说明和错误处理规则：供开发与人工审查。

用户给 Agent 的最短指令可以是：

> 请读取 LanFlow 仓库中的 `docs/import-manifest.schema.json`，按 schemaVersion 1.0 生成 `import-manifest.json`。只输出该 JSON 文件，不要修改 LanFlow 的 `config.json`。

发布后可将 schema 的固定 GitHub Raw 地址写入 `$schema` 字段。Agent 支持读取仓库时，应优先读取仓库内文件；不支持时，用户可把 schema 或示例文件直接交给 Agent。

### 3.3 先预览，后一次性落盘

读取文件、校验和预览阶段不得修改当前配置。只有用户点击“确认导入”后，才在内存副本上完成合并，并调用一次 `ConfigStore.Save`。这样可以避免半成功状态，也能复用现有临时文件加原子替换的保存机制。

## 4. `import-manifest` v1.0 契约

### 4.1 最小示例

```json
{
  "$schema": "https://raw.githubusercontent.com/ZergZFZ/LanFlow/main/docs/import-manifest.schema.json",
  "schemaVersion": "1.0",
  "groups": [
    {
      "name": "开发工具",
      "items": [
        {
          "name": "Visual Studio Code",
          "path": "C:\\Users\\Example\\AppData\\Local\\Programs\\Microsoft VS Code\\Code.exe"
        },
        {
          "name": "Windows Terminal",
          "path": "C:\\Program Files\\WindowsApps\\Microsoft.WindowsTerminal.exe"
        }
      ]
    },
    {
      "name": "设计工具",
      "items": [
        {
          "name": "Figma",
          "path": "C:\\Users\\Example\\AppData\\Local\\Figma\\Figma.exe"
        }
      ]
    }
  ]
}
```

### 4.2 字段定义

| 路径 | 必填 | 类型 | 规则 | LanFlow 行为 |
|---|---:|---|---|---|
| `$schema` | 否 | string | 指向 v1.0 schema | 供 Agent、编辑器和校验工具识别，不参与业务合并 |
| `schemaVersion` | 是 | string | v1.0 固定为 `"1.0"` | 首版仅接受精确版本 `1.0` |
| `groups` | 是 | array | 至少一个元素 | 按顺序进入预览 |
| `groups[].name` | 是 | string | 去除首尾空白后不能为空，建议不超过 80 字符 | 用于匹配现有分组或创建新分组 |
| `groups[].items` | 是 | array | 至少一个元素 | 空分组不导入 |
| `groups[].items[].name` | 是 | string | 去除首尾空白后不能为空，建议不超过 160 字符 | 作为启动项目显示名称 |
| `groups[].items[].path` | 是 | string | Windows 完整路径；支持文件、目录和 `.lnk` | 校验、规范化后写入 `LauncherItem.Path` |

### 4.3 明确禁止由 Agent 提供的内部字段

v1.0 不接受以下字段：

- 分组或项目 `id`；
- `settings`；
- `useCount`；
- `IconImage`；
- `collapsed`、`sortMode`；
- 任何要求覆盖现有配置的标记。

导入时由 LanFlow 生成新的 ID，并使用现有默认值：分组采用 `custom` 排序，项目启用，使用次数为 0，图标通过 `ShellIconService` 从最终路径加载。

### 4.4 兼容策略

- schema 使用 `主版本.次版本` 字符串，但首版客户端只接受精确版本 `1.0`；
- v1.0 schema 对对象设置 `additionalProperties: false`，避免 Agent 字段拼写错误被静默忽略；
- 收到其他版本时必须拒绝，并显示当前版本与客户端支持版本；
- 将来新增可选字段时发布新的 schemaVersion，并显式决定旧客户端是兼容还是拒绝，不预设自动兼容；
- JSON Schema 本身固定 `$id`，后续版本不得悄悄改变旧 schema 的含义；
- 示例文件必须通过对应 schema 校验。

## 5. 解析与校验流程

读取 JSON 后按以下顺序处理：

1. **文件级检查**：文件存在、可读、UTF-8、大小在限制内；建议 v1.0 上限为 5 MB；
2. **JSON 语法检查**：捕获行号、列号和错误原因；
3. **版本检查**：确认 `schemaVersion` 精确为 `1.0`；
4. **结构检查**：必填字段、字段类型、空数组和空字符串；
5. **文本规范化**：分组名和项目名执行 `Trim()`；
6. **路径规范化**：要求 `Path.IsPathFullyQualified`，统一比较形式，路径比较使用 `OrdinalIgnoreCase`；
7. **快捷方式处理**：复用 `ShortcutService` 的既有规则，并在预览中显示最终采用的路径；
8. **存在性检查**：`File.Exists` 或 `Directory.Exists`；不存在或当前不可访问的路径标记为“无效”；
9. **清单内去重**：识别同一目标分组内重复路径；
10. **与现有配置比较**：生成“新建分组”“合并到已有分组”“重复跳过”等预览状态。

解析错误不得导致程序崩溃，也不得修改内存中的 `AppConfig`。

## 6. 分组与项目合并规则

### 6.1 分组匹配

- 分组名去除首尾空白后，使用 `OrdinalIgnoreCase` 与现有分组比较；
- 匹配到现有分组时，显示“合并到已有分组”；
- 未匹配时，显示“新建分组”；
- 清单中多个同名分组先合并成一个预览分组，并给出提示；
- 只有至少一个有效且被勾选的项目时才创建新分组，避免产生空分组。

### 6.2 项目判重

项目唯一性采用：

```text
目标分组 + 规范化后的路径
```

规则：

- 同一分组内相同路径视为重复；
- 同一路径出现在不同分组中允许导入，因为用户可能有意按不同场景组织；
- 与现有项目重复时标记“已存在”，默认不勾选且不可重复导入；
- 清单自身重复时保留第一次出现的项目，其余项标记“清单内重复”；
- 名称相同但路径不同不视为重复；
- 路径相同但名称不同仍视为重复，以路径作为稳定身份。

### 6.3 无效路径

不存在、不是完整路径或无法规范化的项目：

- 在预览中保留并展示错误原因；
- 默认不勾选；
- v1.0 不允许强制导入无效路径；
- 不因单个无效项目阻止其他有效项目导入。

## 7. 导入预览窗口

新增原生 WPF 模态窗口，保持现有 UI 技术边界，不引入 WebView 或第三方 UI 框架。

### 7.1 信息结构

- 顶部：文件名、格式版本、总分组数、总项目数；
- 主体：按分组展示的树形或分组列表；
- 分组行：分组名称、状态、全选/取消选择；
- 项目行：勾选框、名称、路径、状态和错误提示；
- 底部汇总：将新建多少分组、导入多少项目、跳过多少重复项、发现多少无效项；
- 操作：`取消`、`确认导入`。

### 7.2 状态类型

| 状态 | 含义 | 默认选择 |
|---|---|---:|
| 新项目 | 可导入到新分组或现有分组 | 是 |
| 合并分组 | 目标分组已经存在 | 组内有效新项目默认选中 |
| 已存在 | 当前分组已有相同路径 | 否，且不可选 |
| 清单内重复 | JSON 内重复出现 | 否，且不可选 |
| 无效路径 | 路径不存在或格式错误 | 否，且不可选 |

`确认导入` 仅在至少选择一个可导入项目时可用。取消或关闭窗口不得产生任何配置变化。

## 8. 确认、保存与刷新

确认导入时执行：

1. 根据用户选择构建合并后的 `AppConfig` 内存副本；
2. 为新分组和新项目生成 LanFlow 内部 ID；
3. 新分组追加到现有分组末尾，项目保持清单内顺序；
4. 调用一次 `ConfigStore.Save(mergedConfig)`；
5. 保存成功后替换或刷新 `MainViewModel` 当前配置；
6. 为新项目加载图标；
7. 刷新分组、项目列表、空状态和状态栏；
8. 显示结果摘要。

若保存失败：

- 保持原有内存配置不变；
- 显示可理解的错误信息；
- 不报告部分成功；
- 保留导入预览，允许用户修复问题后重试。

## 9. 代码结构与最小改动范围

当前最新版已将平台无关模型、配置存储和主 ViewModel 放入 `LanFlow.Core`。导入解析和合并规则也应进入 Core，WPF 项目只负责文件选择、预览和用户确认。

### 9.1 建议新增

```text
native/LanFlow.Core/
├── Models/ImportManifest.cs              # manifest DTO、预览结果和状态模型
└── Services/ImportManifestService.cs     # 解析、规范化、校验、判重、合并

native/LanFlow.Desktop/
└── Views/
    ├── ImportPreviewWindow.xaml          # 导入预览 UI
    └── ImportPreviewWindow.xaml.cs       # 勾选交互与确认结果

docs/
├── import-manifest.schema.json           # 机器可读契约
└── import-manifest.example.json          # 最小可用示例
```

### 9.2 建议修改

| 文件 | 最小修改 |
|---|---|
| `native/LanFlow.Desktop/MainWindow.xaml` | 在底部工具区增加“导入”图标按钮 |
| `native/LanFlow.Desktop/MainWindow.xaml.cs` | 文件选择、调用导入服务、打开预览、确认后刷新 |
| `native/LanFlow.Core/ViewModels/MainViewModel.cs` | 增加安全应用合并结果或重新加载配置的方法 |
| `native/LanFlow.Core/Services/ConfigStore.cs` | 仅在需要时暴露配置路径/加载接口；保留现有原子保存方式 |
| `native/LanFlow.Desktop/GlobalUsings.cs` | 按现有风格补充必要命名空间 |

不建议把 JSON 解析、去重和合并规则全部写进 `MainWindow.xaml.cs`。这会继续加深主窗口职责，导致规则难以测试，也会让未来其他客户端无法复用。

## 11. 测试矩阵

### 11.1 JSON 与版本

- 合法 v1.0 清单；
- JSON 语法错误并包含行列信息；
- 缺少 `schemaVersion`；
- 非 `1.0` 的格式版本；
- 缺少 `groups` 或数组为空；
- 多余字段、错误类型、空名称；
- 超过文件大小限制；
- UTF-8 中文分组和软件名称。

### 11.2 路径

- 有效 EXE；
- 有效普通文件；
- 有效目录；
- 有效 `.lnk`；
- UNC 路径；
- 相对路径；
- 不存在路径；
- 大小写和斜杠形式不同但实际相同的路径；
- 路径包含空格、中文和特殊字符。

### 11.3 合并与去重

- 全部创建新分组；
- 全部合并到已有分组；
- 同一清单出现多个同名分组；
- 清单内部重复路径；
- 与现有配置重复；
- 同一路径导入不同分组；
- 同名不同路径；
- 新分组所有项目都无效或被取消；
- 部分项目有效、部分重复、部分无效。

### 11.4 事务与 UI

- 预览后取消，配置不变；
- 取消全部勾选，确认按钮禁用；
- 保存成功后只新增所选项目；
- 模拟保存失败，原配置和界面状态保持不变；
- 导入后立即启动新项目；
- 重启 LanFlow 后导入结果仍存在。

## 12. 完成标准

满足以下条件才视为功能完成：

1. 任意 Agent 只要读取 schema 和示例，无需了解 `AppConfig` 即可生成可导入文件；
2. LanFlow 对格式错误给出明确提示，不崩溃、不改配置；
3. 用户确认前，配置文件和内存配置均不变化；
4. 预览能区分新建、合并、重复和无效项目；
5. 用户可以按分组或项目取消选择；
6. 确认后只保存一次，失败时不产生部分结果；
7. 不覆盖现有设置、已有分组属性和已有项目；
8. 导入后的项目沿用既有图标加载与启动调用链；真实桌面交互确认边界见第 10 节验证记录；
9. Release 构建通过，Core 规则测试通过；
10. 现有手工添加、文件拖放和编辑调用链静态回归通过；真实桌面点击确认边界见第 10 节验证记录。

## 13. 已知风险与后续扩展

### 13.1 已知风险

- 快捷方式可能携带参数或工作目录，而现有 `ShortcutService` 主要解析目标路径；v1.0 应与当前行为保持一致，并在测试中确认不会误导用户；
- 网络盘和可移动盘可能暂时不可访问，v1.0 会将其视为无效；后续可增加“允许导入暂不可用路径”的显式选项；
- `MainViewModel.Config` 已采用“保存成功后安全交换”方案：保存前只操作深拷贝，持久化成功后才替换当前配置，并按 ID 保留选择；后续修改不得把 UI 通知重新放入持久化提交边界；
- `AppConfig` 虽位于 `LanFlow.Core`，命名空间仍使用 `LanFlow.Desktop.*`；本功能不应顺带进行大范围命名空间重构。

### 13.2 后续版本候选

以下能力不得挤入 v1.0，可在契约升级后单独设计：

- 命令、参数和工作目录；
- URL、Windows Store App 和协议启动；
- 自定义图标来源；
- 导入策略选项，例如覆盖显示名称；
- 导入历史与一键撤销；
- 在 LanFlow 内复制“给 AI 的格式说明”；
- Agent 直接调用的本地 IPC、CLI 或插件接口。
